## Request format

Every proxied request uses this path shape:

```txt
/{region}/{riot-api-path}
```

The first segment must be a known Riot routing region or platform prefix. Everything after it must match a route in RiftRelay's generated Riot API route registry; unknown hosts and paths return `400` so they cannot bypass method bucketing.

```sh
curl "http://localhost:8985/europe/riot/account/v1/accounts/by-riot-id/Someone/EUW1"
```

That becomes `https://europe.api.riotgames.com/riot/account/v1/accounts/by-riot-id/Someone/EUW1`. Match, summoner, and every other Riot endpoint follow the same pattern.

## Request headers

RiftRelay injects a configured token automatically. Don't send your token from the client.

### `X-Priority`

Send `X-Priority: high` for latency-sensitive requests. It skips pacing delay but still respects rate limits. See [priority requests](/docs/guides/priority-requests).

### `X-Rate-Budget`

Send `X-Rate-Budget: <id>` to use a server-configured pacing budget. Unknown IDs return `400`. See [rate budgets](/docs/guides/rate-budgets).

### `X-Riot-Token-Index`

Pass a token's 0-based index to select it explicitly. `RIOT_TOKEN` entries come first, followed by `RIOT_PINNED_TOKEN` entries. Omit the header and RiftRelay picks the best available `RIOT_TOKEN`; it never automatically selects a `RIOT_PINNED_TOKEN`. Out-of-bounds values return `400`.

```text
RIOT_TOKEN=token-a,token-b
RIOT_PINNED_TOKEN=rso-rate-limit-slot
```

In this example, the RSO rate-limit slot has index `2`. The order of the environment-variable declarations does not affect token indices.

### `Authorization: Bearer`

Bearer-authenticated RSO requests must select an index from `RIOT_PINNED_TOKEN`. This gives the RSO client independent rate-limit state and prevents its response headers from changing the state of a normal API key. RiftRelay forwards the validated `Authorization` header and removes `X-Riot-Token` before sending the request upstream.

```sh
curl \
  -H "Authorization: Bearer $RSO_ACCESS_TOKEN" \
  -H "X-Riot-Token-Index: 2" \
  "http://localhost:8985/europe/riot/account/v1/accounts/me"
```

Missing or automatically selectable indices return `400`. Unsupported authorization schemes and empty Bearer tokens also return `400`.

## Timeouts

Requests can sit in the admission queue before being forwarded. `ADMISSION_TIMEOUT` controls how long that's allowed to take, and `UPSTREAM_TIMEOUT` caps each Riot API attempt, including reading the response body. Failed `GET` responses are retried before the client sees a status; see [upstream retries](/docs/reference/endpoints#upstream-retries). See [configuration](/docs/reference/configuration).

## Errors

Standard HTTP codes: `400` for bad paths, `429` when the queue is full or admission times out, `502` for upstream failures, `504` for upstream timeouts. Full table in [endpoints](/docs/reference/endpoints#error-behavior).

## Tips

Keep `RIOT_TOKEN` on the server only. Route all Riot traffic through RiftRelay — mixing direct and proxied calls defeats the purpose of centralized rate limiting. Default to normal priority; `X-Priority: high` loses its value if everything is high.
